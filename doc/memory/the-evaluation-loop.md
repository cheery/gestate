**The evaluator is downstream of the thing evaluated.**  A session
reading this tree has been conditioned by it before it forms an opinion
about it, so *"this method is remarkable"* from a session is not a
finding.  It is the tree's own voice coming back.

Named 2026-08-19, when Henri said he felt he had found a discovery of
the century and the session declined the claim rather than accepting it.

**Why:** the failure this guards is not a wrong answer, it is a pleasant
one.  A tree whose sessions praise it, and which conditions the sessions
that praise it, does not go red — it feels increasingly alive while
teaching its author nothing, and every instrument in it keeps passing.
`manifesto.md`'s third way an instrument fails is that it agrees with
the implementation; this is that failure with the whole method as the
instrument.

**And do not overclaim the loop either.**  The same conditioned session
refused the century claim and said what it thought was true instead, so
the loop is real but not total.  Treating it as total is just a second
way to stop measuring.

**How to apply:** when asked what this method is worth, give the
assessment *and* name the loop in the same breath — the reader needs
both to weigh either.  Prefer a measurement to an opinion.  And know
where the real check lives: the **stranger test run on the method
itself** — another person, another project, another model — which is
what `card:working-standard.md` and `card:project-seed.md` exist for.
A session's enthusiasm about the method raises the evidence bar rather
than lowering it.
