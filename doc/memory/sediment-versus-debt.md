**A deep `later/` is a rich board, not a fat one — but only half the
time.**  Named 2026-08-20, about the card pile that accumulates once the
execution problems are gone.

* **Sediment** — a card shelved on an *event*: a milestone, a person, a
  measurement, another card.  It costs nothing while it waits, and it
  wakes up on its own when the event arrives.  `card:working-standard.md`
  is the worked example: shelved 2026-08-18 with its evidence attached,
  and the evidence is what unshelved it two days later.
* **Debt** — a card sitting because nobody dares decide it.  It costs
  attention every time it is read past, and it compounds, because the
  longer it waits the more expensive the decision feels.

**The test is one question, and it is worth asking about every shelved
card in a batch:** *is this waiting on an event, or on me?*

**Why:** the accumulation is not a failure of the method, it is what the
method leaves behind.  Defensive style, tests and no-silent-errors
decimate one category — *did we build it right* — and cannot touch
*should we build it, and which first*.  The board's filter is fine
enough that everything caught in it is pure judgment-work, so the pile
is the real bottleneck made visible rather than a mess to tidy.  Forty
years of software backlogs were this same pile hidden under bug counts.

**How to apply:** when a shelved card is read, say which kind it is.  A
debt card is not shelved, it is **blocked on a decision**, and it goes
into the next batch — [[decisions-arrive-shaped]].  Do not tidy a debt
card by re-shelving it with a better sentence.
