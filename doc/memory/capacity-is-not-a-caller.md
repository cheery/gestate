**Asked 2026-08-20:** *"I can make incredibly lot of software with this
method then.  should I?"*  The answer is mostly **no**, and the method
already contains it.

**Overproduction is the first and worst of the seven wastes** — making
things because capacity exists rather than because demand does — and it
is ranked worst because it manufactures the others: inventory, defects,
and attention spent keeping unwanted things alive.  The board states the
same law in its own words: **a `because` is a problem, never a fix.  "I
can" is not a `because`, and a capacity is not a caller.**

**The hidden cost is that software is not written, it is kept.**  Every
program is a standing claim on the one resource this method never
multiplied — review, direction, the keeper's attention.  Ten projects is
ten camps, and there is one evening a week ([[the-keepers-evening]]).
The 270-commits-in-nine-days lesson was exactly that production outruns
the keeper; worsening that ratio on purpose, with the lesson dated in
the tree, is [[the-evaluation-loop]]'s failure mode arriving as work.

**Three legitimate pulls, in order:**

1. **Depth over count.**  Gestate finished to its vision — the stranger
   test passing, instruments editable while they sound, the friend using
   it.  That demand already exists, which is what makes it a pull.
2. **The vessel.**  The environment that lets others, future selves or
   smaller models make software safely inside it.  Making software is
   linear; making the thing that makes software safe compounds —
   [[mechanism-not-instructions]], [[smaller-models-and-the-tree]].
3. **Experiments, budgeted.**  Cheap, reversible, timeboxed, deleted
   without ceremony.  Exploration is a pull too, and the puller is a
   question — never a fleet of orphans each needing a keeper.

**How to apply:** the first thing a factory tempts its owner to do is
run it at capacity, and the refusal of that temptation is the founding
move of the method this tree borrows from.  Make exactly as much
software as has a `because`.  The rest is inventory.  In practice, for a
session: **do not propose new projects, new tools, or new cards on the
grounds that they would be easy** — that is the capacity talking, and it
is not a caller.  Related: [[gestate-board-goal]], [[sediment-versus-debt]].
