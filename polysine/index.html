# The same sine, made an instrument: four voices, a keyboard and a piece.
#
#   python -m gestate.audioperform examples/audio/polysine.ges -o polysine.wav
#   python -m gestate.audioperform examples/audio/polysine.ges --midi
#   python -m gestate.audioeditor examples/audio/polysine.ges
#
# `sine.ges` is one note with its start and end written down as constants.
# This is what it takes to stop writing them down — and it is four lines,
# which is the point of the file.
#
# **A voice is an expression over signals.**  A `voices` bank hands each of
# its voices two: a `Sig Gate`, which says when the note began and when it
# was released, and a `Sig Key`, this program's own payload.  A pitch reads
# the second and an envelope reads the first, so neither has to open a
# record to find its half:
#
#   * `!hzOfKey s`      — the note's frequency, lifted over the payload
#   * `adsr env g`  — the envelope, from the timing
#   * `sine hz`     — an oscillator that follows a frequency *signal*
#
# and `Num (Sig Float)` makes `*` mean what it looks like.  So the voice is
# a product of three signals, and nothing here declares state, folds it, or
# takes a note apart per sample.
#
# It used to.  `spec/frp_lesson.md` is the reading that says why that was
# worth fixing: beside Fran, where `stretch (abs wiggle) charlotte` applies
# ordinary functions to things that vary, a synth written as a hand-rolled
# state machine is ceremony in the way of its own subject.  What that cost
# was four gaps in the compiler, not a new language.  `fmpoly.ges` and
# `polysaw.ges` still write their voices out the long way, and are worth
# reading against this one.

#: What a note of this instrument is.  Its **timing is not in it**: that
#: comes from the layout that placed the note, or from the moment a key
#: went down, and the bank supplies it as a `Sig Gate` beside this one.
#:
#: Called `Key` and not `Note`, because `music.ges` declares
#: `Score a := Note a` and `'x` desugars to that constructor — shadowing it
#: would make every `'` in the piece below a pattern against the wrong
#: thing.  A payload may also be a bare `Int` or `Float` when a note number
#: is all a voice needs; this one carries velocity too.
Key := Key Int Int                          # key number, velocity

#: Four voices, so four notes can sound at once.  The bank's name is bound
#: to the *sum* of them, which is why `sound` below is ordinary signal code.
voices lead 4 sineVoice : Sig Float

#: How a MIDI note becomes this payload — `Nothing` would decline it.  It
#: says the payload *can* come from a keyboard, not that this bank listens:
#: which bank the keyboard drives is a switch in the editor, beside the
#: bank's own line.
instance FromMIDI Key where
    noteOn ch p v = Just (Key p v)

env : Adsr
env = Adsr 0.01 0.25 0.6 0.3

hzOfKey : Key -> Float
hzOfKey q = case q of
    Key k v -> keyHz k

velOfKey : Key -> Float
velOfKey q = case q of
    Key k v -> toFloat v / 127.0

sineVoice : Sig Gate -> Sig Key -> Sig Float
sineVoice g s = sine (!hzOfKey s) * adsr env g * !velOfKey s

# ── The piece ────────────────────────────────────────────────────────────
#
# `||` overlays and `++` sequences, so the chord is three notes sharing a
# span — three of the four voices, which a monophonic synth could not play.
# `voices.lead` names the bank *lexically*, and that is what lets the type
# checker say this piece fits this instrument rather than leaving you to
# discover it as silence.

bpm : Int
bpm = 96

chord : Int -> Int -> Int -> [: Key :]
chord a b c = '(Key a 96) || '(Key b 84) || '(Key c 78)

tune : [: Key :]
tune = '(Key 60 100) ++ '(Key 64 100) ++ '(Key 67 100) ++ chord 60 64 67

score : [: Void :]
score = tune >>= voices.lead

#: 0.35, not 0.5: the bank's name is the *sum* of its voices, so three
#: notes at once are three times the amplitude and a level set by ear on a
#: single note clips on the chord.
sound : Sig Float
sound = gain 0.35 lead
