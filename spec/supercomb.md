Supercombinators combinators
============================

The implementation has two phases:

  1. **Lambda lifting** -- input uses the `Expr` grammar with `ELambda`;
     output is an equivalent set of closed supercombinators (no *nested*
     `ELambda`; each SC keeps one outer wrapping `ELambda` carrying its
     parameter list).
  2. **G-machine codegen** -- the `ELambda`s are gone (lift peels each
     SC's outer wrapper before codegen); the G-machine compiler rejects
     any `ELambda` it sees inside `compileC`, see below.

Both phases share the same `Expr` grammar.

Grammar
-------

    Expr := EGlobal Name
          | EVar Name
          | ENum Int
          | ECon Tag [Expr]
          | EAp Expr Expr
          | ELet IsRec [(Name, Expr)] Expr
          | ECase Expr [Alter]
          | ELambda [Name] Expr
          | ETuple [Expr]
          | EProj Int

    Name          := str | int       -- str is a "Known" source id; int is
                                     -- an "Anon" lambda-lifted SC id
    Arity         := Int
    Tag           := Int
    IsRec         := Bool
    Alter         := (Tag, [Name], Expr)

* `(str s)` is a source identifier (whether a global SC or a local
    binder); `(int n)` is the id of a lambda-lifted SC generated by
    the lifter.  The lifter never reuses a lifted id; the integer id
    namespace is disjoint from the `(str s)` identifiers.  The Python
    implementation drops the `Known`/`Anon` dataclasses and uses
    `Union[str, int]` directly (see `expr.py`).
  * `EVar n`: the bound variable whose binder name is `n`.  An `EVar`
    never carries a global id; only `EGlobal` does.
  * `ECon t args`: data constructor of tag `t` applied to `args`.
  * `ELet rec defs e`: `defs` is a list of `(Name, Expr)` pairs in
    left-to-right source order.  After compilation the values occupy
    contiguous stack slots `[0..n-1]`; the i-th pair's value lives at
    offset `n-1-i` (last-pushed is topmost).  When `rec` is true the
    binders may reference each other; otherwise each def may reference
    only outer (older) binders.
  * `ECase scrut alts`: evaluate `scrut` to WHNF, dispatch on its tag.
  * `ELambda params body`: binds the binder names in `params` (a list,
    source order).  At the SC top level a single `ELambda` wraps the
    source SC's parameter list; lambda lifting turns every *nested*
    `ELambda` into a top-level `(int_id, ELambda(frame_params,
    lifted_body))` SC and replaces the lift-site with an
    `EAp`/`EGlobal(int_id)` chain that supplies the captured free
    variables as additional args.  Any `ELambda` the G-machine compiler
    sees inside `compileC` is an error (see below).
  * `ETuple args`: an n-ary tuple of `args` (length `n >= 2`; the
    nullary and unary cases are syntactic non-sequiturs and the parser
    rejects them).  Tuples are NOT data constructors -- they have no
    `Tag` and are not matched by `ECase`; they live in a distinct
    runtime node form (`NTuple`, see below).  Field access is via
    `EProj i` applied to the tuple, never via `ECase`.
  * `EProj i`: the i-th field selector (a partial expression).  Legal
    source positions are exactly `EAp (EProj i) tup` where `tup` is
    some tuple-valued `Expr`; a bare `EProj i` is a compile error (it
    is not a first-class value, mirroring `Pack`).  Indices are
    0-based; `i` must be a valid field of `tup`'s arity (checked at
    runtime when `tup` evaluates to an `NTuple`).

Lambda lifting
--------------

Implements the algorithm of
"Simple Lambda Lifting: Formalisation In Lean and a new efficient algorithm".

    EP   := Map Function (Set Variable)    -- extra params needed per fn
    work := Stack (Function, Variable)

    for v in all_variables:
        for f in functions that reference v as a non-local:
            EP[f] := EP[f] ∪ {v}
            push (f, v) onto work

    while work is not empty:
        (f, v) := pop work
        for g in functions that reference f:
            if g ≠ decl(v) and v ∉ EP[g]:
                EP[g] := EP[g] ∪ {v}
                push (g, v) onto work

    return EP

`EP[f]` is the set of free variables that must be added to `f`'s
parameter list.  The lifter assigns each lifted SC a fresh `int` id,
chooses a deterministic order for `EP[f]` (alphabetical), and emits
its outer `ELambda` as `ELambda(extras ++ own_params, lifted_body)`
-- extras first, own_params last -- because at the lift-site the
extras are applied innermost (becoming `a_0, a_1, ...`) and the caller
applies the own_args outermost (becoming `a_k, ...`).  The lift-site
itself rewrites the original nested `ELambda` into a partial
application `EAp-EGlobal(int_id) ... ` supplying only the captured
free variables; the caller's own_args are spliced in by the original
application structure (unchanged).

The G-machine
-------------

Follows "Implementing Functional Languages: a tutorial".

    GmState  := (GmCode, GmStack, GmHeap, GmGlobals, GmDump)

    GmCode   := [Instruction]

    Instruction := Unwind
                 | PushGlobal Name
                 | PushInt Int
                 | Push Int          -- push the cell at stack offset n (let/case binder)
                 | PushArg Int       -- push the arg of the NAp at stack offset n+1 (SC param)
                 | Mkap
                 | Update Int
                 | Pop Int
                 | Alloc Int
                 | Slide Int
                 | Eval
                 | Pack Tag Arity
                 | PackTuple Arity
                 | Proj Int
                 | CaseJump [(Tag, GmCode)]

    GmStack  := [Addr]
    GmHeap   := Map Addr Node
    GmDump   := [(GmCode, GmStack)]        -- saved frames for `Eval`
    GmGlobals := Map Name Addr

    Node := NNum Int              -- numbers
           | NAp Addr Addr         -- applications
           | NGlobal Arity GmCode  -- globals
           | NInd Addr             -- indirection; the address may be null
           | NCon Tag [Addr]       -- saturated constructor application
           | NTuple [Addr]         -- saturated tuple (no tag; arity = length addrs)

Helpers:

    getCode : GmState -> GmCode
    putCode : GmCode -> GmState -> GmState

    getStack : GmState -> GmStack
    putStack : GmStack -> GmState -> GmState

    getHeap : GmState -> GmHeap
    putHeap : GmHeap -> GmState -> GmState

    getGlobals : GmState -> GmGlobals

    -- push/pop a (code, stack) frame for `Eval`
    pushDump : (GmCode, GmStack) -> GmState -> GmState
    popDump  : GmState -> (GmCode, GmStack, GmState)
    isDumpEmpty : GmState -> Bool

Evaluator:

    evaluate : GmState -> GmState
    evaluate s | gmFinal s = s
               | otherwise = evaluate (step s)

    gmFinal : GmState -> Bool
    gmFinal s = isEmpty (getCode s) && isDumpEmpty s

    step : GmState -> GmState
    step s = dispatch i (putCode is s)
             where (i:is) = getCode s

    dispatch : Instruction -> GmState -> GmState
    dispatch Unwind         = unwind
    dispatch (PushGlobal f) = pushglobal f
    dispatch (PushInt n)    = pushint n
    dispatch (Push n)       = push n
    dispatch (PushArg n)    = pusharg n
    dispatch Mkap           = mkap
    dispatch (Update n)     = update n
    dispatch (Pop n)        = pop n
    dispatch (Alloc n)      = alloc n
    dispatch (Slide n)      = slide n
    dispatch Eval           = eval
    dispatch (Pack t a)     = pack t a
    dispatch (PackTuple a)  = packtuple a
    dispatch (Proj i)       = proj i
    dispatch (CaseJump t)   = casejump t

Stack indexing convention:  `stack !! 0` is the topmost cell.

Stack layout at supercombinator entry: when `Unwind` enters an
`NGlobal` of arity N the stack is `[SCo, Ap_0, Ap_1, ..., Ap_{N-1},
...older...]` (topmost first), where `Ap_k = NAp(Ap_{k-1}, a_k)` and
`Ap_0 = NAp(SCo, a_0)`.  The SCo node itself remains at `stack!!0`;
the parameter that the source code calls `params[i]` lives behind the
`NAp` at `stack!!(i+1)` and must be fetched by following that `NAp`'s
argument pointer.  This is what `PushArg` is for; `Push` (which reads
a cell verbatim) is reserved for `let`/`case` binders that already sit
on the stack as standalone cells.  The compiler therefore assigns
`params[i] -> Arg i` in source order (the i-th source param -> the
i-th `NAp` away from `SCo` -> `PushArg i`).

Instruction semantics:

    pushglobal f s
        a := getGlobals s ! f           -- errors if f is not present
        s := push a onto (getStack s)

    pushint n s
        (a, h) := hAlloc (getHeap s) (NNum n)
        s := putHeap h; push a onto stack

    mkap s
        a1:a2:rest := stack    -- a1 = topmost = the function, a2 = the arg
        (a, h)     := hAlloc (getHeap s) (NAp a1 a2)
        s := putHeap h; putStack (a : rest)

    push n s = push (stack !! n) onto stack

    pusharg n s
        ap := stack !! (n + 1)
        case ap of
            NAp _ arg -> push arg onto stack
            _         -> error "PushArg: stack slot is not an NAp"

    slide n s
        a:rest := stack
        s := putStack (a : drop n rest)

    update n s
        a:rest := stack          -- a = the freshly-evaluated cell
        h := getHeap s
        -- overwrite the n-th cell of `rest` to be an indirection to `a`
        h := hUpdate h (rest !! n) (NInd a)
        s := putHeap h; putStack rest

    pop n s = putStack (drop n stack) s

    alloc n s
        -- allocate n `NInd null` cells and push them in order; the
        -- last-allocated one ends up on top of the stack.
        repeat n times:
            (a, h) := hAlloc h (NInd null)
            stack := a : stack
        s := putHeap h; putStack stack

    unwind s
        a := top of stack               -- not removed
        case getHeap s ! a of
            NNum _         -> s                 -- already WHNF, do nothing
            NAp x _        -> s { stack = x : stack;   code = [Unwind] }
            NGlobal n c    -> if length stack < n + 1
                              then error "Unwinding global with too few args"
                              else s { code = c }   -- SCo stays at stack!!0
            NInd b         -> s { stack = replaceTop b stack; code = [Unwind] }
            NCon _ _       -> s                 -- already WHNF
            NTuple _       -> s                 -- already WHNF

    eval s
        a := top of stack
        s := popDump-safe pushDump (getCode s, drop 1 stack) s
        s := putCode [Unwind] s
        s := putStack [a] s

    -- When the code becomes empty and the Dump is non-empty, an
    -- `Eval`-driven `Unwind` has just reached WHNF: the result sits on
    -- top of the current (mini) stack, and the saved frame holds the
    -- caller's stack minus the evaluated expr.  Restore by prepending
    -- the result to the saved stack:
    -- if isEmpty (getCode s) && not (isDumpEmpty s):
    --     let (c, st, s') = popDump s
    --     in s' { code = c, stack = head stack : st }

    pack t a s
        (args, rest) := splitAt a stack     -- args[0]=topmost (last arg)
        (nAddr, h)   := hAlloc h (NCon t (reverse args))
        s := putHeap h; putStack (nAddr : rest)

    -- `PackTuple a` is the tuple analogue of `Pack`: pop `a` args, push
    -- an `NTuple` (no tag) holding them in source order (first source
    -- arg leftmost).
    packtuple a s
        (args, rest) := splitAt a stack     -- args[0]=topmost (last arg)
        (nAddr, h)   := hAlloc h (NTuple (reverse args))
        s := putHeap h; putStack (nAddr : rest)

    -- `Proj i` selects the i-th (0-based, source order) field of the
    -- tuple on top of the stack.  Caller has already done `Eval`, so
    -- the top of stack is guaranteed to be in WHNF.
    proj i s
        a := top of stack
        case getHeap s ! a of
            NTuple addrs ->
                if i < 0 || i >= length addrs
                  then error "Proj: index out of range"
                  else s { stack = addrs !! i : drop 1 stack }
            _ -> error "Proj on non-tuple"

    casejump table s
        a := top of stack
        case getHeap s ! a of
            NCon t args ->
                alt := lookup table t            -- errors if missing
                -- discard the scrutinee cell, push the args REVERSED
                -- (so the LAST source-field ends up topmost -- offset 0).
                -- Source field i therefore maps to Local (a-1-i):
                --   names[0] -> Local (a-1) (deepest)
                --   names[a-1] -> Local 0 (topmost)
                rest    := drop 1 stack
                newStack := reverse args ++ rest
                s := putStack newStack
                s := putCode (alt ++ getCode s) s
            _ -> error "CaseJump on non-constructor"


Compiler
--------

    compile :: CoreProgram -> GmState
    compile program = (initialCode, [], h, g, [])
        where (h, g) = buildInitialHeap program

    initialCode = [PushGlobal "main", Unwind]

    buildInitialHeap :: [(Name, Arity, Expr)] -> (GmHeap, GmGlobals)
    buildInitialHeap program
        = foldr allocate (emptyHeap, emptyGlobals) program
      where
        -- Each SC decl is `(name, arity, ELambda params body)` with
        -- `arity = length params`.  Unwrap the lambda here.
        allocate (name, arity, ELambda params body) (h, g)
            = let code = compileSc body params
                  (a, h') = hAlloc h (NGlobal arity code)
              in (h', g |-> name ↦ a)

Each supercombinator is compiled as follows.

    -- At SC entry the spine of `NAp` nodes sits below the `NGlobal` on
    -- the stack, so a parameter must be fetched by navigating the i-th
    -- `NAp` (`PushArg`).  A `let`/`case` binder, by contrast, is a
    -- standalone cell on the stack and is read directly (`Push`).  The
    -- environment therefore carries, per binder name, which kind of
    -- reference it is.
    StackRef := Arg Int | Local Int
    Env      := Map Name StackRef     -- keyed by binder name

    bump :: StackRef -> StackRef
    bump (Arg n)   = Arg (n + 1)
    bump (Local n) = Local (n + 1)

    pushRef :: StackRef -> [Instruction]
    pushRef (Arg n)   = [PushArg n]
    pushRef (Local n) = [Push n]

    -- Source order mapping: param `params[i]` is the (i+1)-th-applied
    -- arg (caller's source code applies them left-to-right).  At SC
    -- entry the i-th-applied arg lives behind the i-th `NAp`,
    -- fetchable via `PushArg i`.  Source SCs and lifted SCs share
    -- this rule: the lifter builds `frame = extras ++ own_params` so
    -- that `frame[0]` is the innermost-applied (an extra) and
    -- `own_args` are outermost-applied (because the caller wraps them
    -- around the partial application).
    compileSc :: Expr -> [Name] -> GmCode
    compileSc body params = compileR body env (length params)
      where env = zip params (map Arg [0 .. length params - 1])

    compileR :: Expr -> Env -> Arity -> GmCode
    compileR e env arity = compileC e env
                       ++ [Update arity, Pop arity, Unwind]

    compileC :: Expr -> Env -> GmCode

    compileC (EGlobal n)    env = [PushGlobal n]
    compileC (EVar n)       env = pushRef (env ! n)     -- errors if absent
    compileC (ENum n)       env = [PushInt n]

    compileC (ECon t args) env
        = concat (compileArg args 0)
       ++ [Pack t (length args)]
      where
        compileArg []     _ = []
        compileArg (a:as) i = compileC a (mapEnv (applyN bump i) env)
                          ++ compileArg as (i+1)

    -- Tuples compile like `ECon`s but use `PackTuple` (no tag); the
    -- fields are emitted left-to-right (same source-order convention
    -- as `Pack t a`: the topmost stack cell after the field-eval
    -- sequence is the LAST source field; `packtuple` reverses them).
    compileC (ETuple args) env
        = concat (compileArg args 0)
       ++ [PackTuple (length args)]
      where
        compileArg []     _ = []
        compileArg (a:as) i = compileC a (mapEnv (applyN bump i) env)
                          ++ compileArg as (i+1)

    -- `EAp (EProj i) tup` is the legal projection form.  We compile
    -- the tuple, force it to WHNF with `Eval`, then select field `i`
    -- via `Proj`.  This case MUST come before the generic `EAp` rule
    -- so a projection is never wrapped into an `NAp` node.
    compileC (EAp (EProj i) tup) env
        = compileC tup env
       ++ [Eval, Proj i]

    compileC (EAp x y) env
        = compileC y env
       ++ compileC x (mapEnv bump env)
       ++ [Mkap]

    compileC (ELet rec defs e) env
        | rec       = compileLetrec defs e env
        | otherwise = compileLet    defs e env

    compileC (ECase scrut alts) env
        = compileC scrut env
       ++ [Eval, CaseJump (map mkAlt alts)]
      where
        mkAlt (tag, names, body) =
            let a        = length names
                -- Source field i maps to Local (a-1-i) (see casejump
                -- semantics): topmost = last source field.
                envLocal = extendEnvList [ (names !! i, Local (a-1-i))
                                         | i <- [0 .. a-1] ]
                                        (mapEnv (applyN bump a) env)
            in (tag, compileC body envLocal ++ [Slide a])

    compileC (ELambda _ _) env
        = error "ELambda reached the G-machine compiler; \
                \lambda lifting did not run"

    compileC (EProj i) env
        = error "EProj must be applied to a tuple; \
                \bare EProj is not a first-class value"

    -- Non-recursive let: defs are pushed left-to-right; while
    -- compiling def i only the outer (older) binders are visible
    -- (defs may not see each other).  Once all `n` are pushed the
    -- body sees them at offsets [n-1, n-2, .. 0] from the top, so the
    -- i-th source-pair's binder is at Local (n-1-i).  `Slide n` runs
    -- AFTER the body so the body's result survives while the def
    -- cells are discarded.
    compileLet :: [(Name, Expr)] -> Expr -> Env -> GmCode
    compileLet defs e env
        = go 0 defs
       ++ compileC e envBody
       ++ [Slide n]
      where
        n       = length defs
        go _ []         = []
        go i ((nm, d):ds) = compileC d (mapEnv (applyN bump i) env) ++ go (i+1) ds
        envBody = extendEnvList [ (fst (defs !! i), Local (n-1-i))
                                | i <- [0 .. n-1] ]
                               (mapEnv (applyN bump n) env)

    -- Recursive let: allocate n indirection placeholders (`Alloc n`),
    -- compile each def against the placeholder env (so it may refer
    -- to every other def), and `Update` each placeholder in turn with
    -- the resulting WHNF cell.  Compile the body in the same env, then
    -- `Slide n` to drop the placeholders.
    compileLetrec :: [(Name, Expr)] -> Expr -> Env -> GmCode
    compileLetrec defs e env
        = [Alloc n]
       ++ concat (zipWith [0 ..] defs
                          (\i (nm, d) -> compileC d envLocal
                                         ++ [Update (n-1-i)]))
       ++ compileC e envLocal
       ++ [Slide n]
      where
        n        = length defs
        envLocal = extendEnvList [ (fst (defs !! i), Local (n-1-i))
                                 | i <- [0 .. n-1] ]
                                (mapEnv (applyN bump n) env)

    -- `applyN f n` is `f` composed with itself `n` times (n >= 0).
    applyN f 0 = id
    applyN f n = f . applyN f (n-1)

    -- `mapEnv` applies a `StackRef -> StackRef` to every value in the
    -- env, leaving the keys alone.  `extendEnvList` adds new
    -- name->ref pairs, shadowing any prior binding for the same name.

`arityOf : Tag -> Arity` is no longer needed: each `Alter` carries
its field names directly (`[Name]`), so its arity is `length names`.

A note on `Update arity`: at the end of an SC body the stack is
`[result, SCo, Ap_0, ..., Ap_{arity-1}, ...caller...]` (the SCo and
the spine `NAp`s are still on the stack from entry).  After `Update
arity` the root redex -- the outermost `NAp`, at `rest !! arity` --
becomes an `NInd result`; `Pop arity` then discards
`[SCo, Ap_0, ..., Ap_{arity-2}]` leaving `[NInd result, ...caller...]`;
`Unwind` chases the `NInd` and restores `result` on top.  For a CAF
(arity 0) the same sequence is harmless: `Update 0` overwrites the
`NGlobal` cell itself (so future `PushGlobal` calls share the cached
result).
