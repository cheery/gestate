# F233. **[resolved]** `shell/clap/src/gui.rs` read fifteen of the descriptor's sixteen tags, so `--features substrate` had not compiled since `Does` was appended

Found 2026-09-16 by turning `exportClap`'s `--gui` on at Henri's ask and
exporting a file that draws:

    error[E0063]: missing field `does` in initializer of `SubTags`
       --> shell/clap/src/gui.rs:288:15

`Does` was appended to `export._SUB_CONS` and the generated descriptor
has carried sixteen tags ever since — `shell/clap/src/descriptor.rs`
line 54 has all sixteen, and the editor's `walk.rs` and the web shell's
`lib.rs` both read `does: t[15]`.  The clap shell's own construction
stopped at `nil: t[14]`.  So `gestate-clap` had not compiled under
`--features substrate` from that day, and the crate's *default* build
was green the whole time.

**Why nobody found out.**  `cargo test --workspace` builds each crate
with its **default** features, and `substrate` is off by default —
`gui` is off because the shell's zero-dependency build is a property
`shell/README.md` is built around.  Nothing in the suite, the gates or
the pre-commit hook ever asked the compiler to look at that file.  The
first caller to reach it was a person exporting a plugin.

**This is F216 one tag later.**  That entry is `Meaning` appended to the
same table with the length left at fourteen in seven places and four
languages.  The lesson recorded there was that a table's length gets
copied further than anybody remembers.  What this adds: **copying it
into code that nothing builds hides the copy**, so the roster check
F216 earned does not help — there was no red to see.

**Resolved the same day**, one line: `does: t[15]` in `gui.rs`, with the
index named in a comment beside it.

**And the hole it came through is closed.**  `tools/suite.py`'s
`FEATURES` now runs `cargo check` over every off-by-default feature in
the workspace — `gestate-clap [substrate,dynscore]`,
`gestate-panel [window,substrate]`, `gestate-editor [capi]` — in the
Rust step, between the gates and the long pass.  **One second warm**,
measured, which is what makes it affordable; `check` rather than `test`
because these have no tests of their own and the question is only
whether they still compile.

The gate was broken on purpose before it was believed: with `does`
removed it reports *gestate-clap [substrate,dynscore] did not compile*
and returns 1, and green again when the line is put back.
`gestate-editor [capi]` is on the list for the reason
`doc/memory/a-build-is-not-an-instrument-until-it-has-failed.md` gives —
a featureless build of that crate compiles none of `window.rs` and says
*Finished*.

**Verified by the thing that found it**: `exportClap` through the
workbench door now builds `fmpoly.ges` (window, no canvas, 9 s),
`lantern.ges` (window and canvas, 12 s) and a nine-bank piece of
Henri's (25 s), and `clap.gui`, `gestate_clap::gui` and
`gestate_panel::window` are in the artifacts.

gate: `tools/suite.py`'s `FEATURES` — the Rust step runs `cargo check`
over every off-by-default feature in the workspace, so this file is
compiled at every full pass.  The gate names this number in its own
note, and it was broken on purpose once before it was believed.
