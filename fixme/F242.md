# F242. **[bug]** a canvas with no `sound` is told it declares no `ticks` — a word its author never typed

**2026-10-02.**  `examples/gui/two-hands.ges` shipped without a `sound`,
and opening it in the window said:

> this file declares no `ticks`, and the player's generated entry needs it.

The window builds every file as a synth too, and the assembly for a file
with no `sound` fails inside the library (`constSig` names `ticks`), so
`audiospans.cli_error`'s sentence — written for exactly this, *"the
author's file lacks the name the player needs"* — names the library's
word instead of the author's.  The `sound` case it already handles is
the one that should have fired.

    python -c "from pathlib import Path; from gestate import audio, notes; \
      audio.render(notes.read(Path('examples/gui/two-hands.ges')).replace('sound = 0.0', ''), seconds=0.01)"

*(After the fix below, take `sound` out of a copy to see it.)*

**What is done:** the example gained `sound = 0.0`, as every other GUI
example has, and `test/test_two_hands.py::test_it_opens_the_way_the_window_opens_it`
compiles it through the player's door — seen failing without the line.
The tests had loaded only the canvas half, which is how it shipped.

**What is not:** the message.  Either a canvas with no `sound` is told
*that*, or the window does not ask a canvas-only file to play at all —
the second is a design question (`vision.md`'s stranger opens a file and
hears it), so it waits for him.
