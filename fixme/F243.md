# F243. **[resolved]** a press on the edge between two regions goes to different elements in the two walkers

**2026-10-02**, found driving `examples/gui/checkboxes.ges`: two rows
stacked by `Column` share the line y = 0, and a press there reached the
upper row in the reference walker.  The two walkers disagree on what a
region holds:

    gestate/gui.py         `_under`:   x0 <= x <= x1 and y0 <= y <= y1     — both edges in
    shell/panel/src/list.rs `contains`: x >= x0 && x < x1 && y >= y0 && y < y1 — half-open

so a press exactly on a shared edge lands on one element in the
reference machine and possibly the other in the window.  `_grabbed` and
`Display::grabbed` are documented as *"kept to the letter"*, and this
letter is not the same.

    python - <<'X'
    import sys; sys.path.insert(0, ".")
    from gestate.gui import _under
    a = {"region": (0, 0, 10, 10)}; b = {"region": (0, 10, 10, 20)}
    print(_under([a, b], 5, 10) is a)   # True: the edge is the upper one's in Python; the lower one's in Rust
    X

**Not fixed.**  Half-open is the usual reading and the Rust one; making
`_under` half-open may move presses some test aims at an edge.  One
line and a suite run, not this slice's.

**Resolved 2026-10-03.**  `_under` is half-open now, as `contains` is —
and so is the roll's probe, `scorebox.note_at`, which answers what
`_under` answers and was the second copy of the inclusive letter
(`test_drawnscores.py`'s probe test went red on the far edge until it
moved too).  Held by `test_gui.py`'s shared-edge test, red with the old
condition.
