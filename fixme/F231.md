# F231. **[open]** a type alias named like a constructor is accepted, and the clash surfaces later as *Unknown global* at a use of the constructor

Found 2026-09-14 while building the seam-1 slice of
`card:strict-forms.md`: the first name for the game's row was `type Row
= $(kindRow markKind)`, and `Row` is `gui.ges`' picture constructor.

`declarations._collect_aliases` refuses an alias whose name is a data
type's or a built-in type's, and says so.  It does not look at
**constructor** names, which the tokenizer keeps in the one namespace
with types (`prelude._type_names` says why: *every `CONID` token of a
shadowed name moves, whether it stood for the type or its
constructor*).  So `type Row = …` beside `Sub := … | Row Sub Sub | …`
is accepted, and the program fails further down with

    Unknown global 'Row' (not defined as a supercombinator or class method)
    while checking `rowPic` (at 3643:18)

— at a line that *uses* the constructor, about a *global*, with the
alias two hundred lines away and unmentioned.  The refusal exists; it
is one namespace short.

**What it should say:** *Type alias 'Row' clashes with a constructor
of the same name*, at the alias, the same shape as the two refusals
beside it.

gate: none yet — a test in `test/test_declarations.py` (or wherever
`_collect_aliases`' two clashes are held) that an alias named like a
constructor is refused at the alias line.
