# F228. **[resolved]** `git commit -a` or `git commit <path>` is refused by a gate that failed for git's reason, not the tree's

Found 2026-09-13 by a session committing a one-line edit to
`board/standing.md` with `git commit -am`.  The pre-commit hook ran
the gates and one went red:

    FAILED test/test_precommit.py::test_the_hook_refuses_a_commit_when_a_gate_says_no
    error: invalid object 100644 b4ef5af… for '.claude/settings.json'
    error: Error building trees

`tools/suite.py --gates` run by hand at the same moment was green, and
`git add` then a bare `git commit` landed.

**The cause, measured:** a commit with `-a` or a pathspec builds a
temporary index and exports `GIT_INDEX_FILE` to its hooks.  The test
makes a scratch repository and runs `git commit` in it from inside
that hook, so the scratch commit read *this* repository's index and
could not find its blobs.  `GIT_INDEX_FILE=$PWD/.git/index python -m
pytest test/test_precommit.py -k refuses_a_commit` fails; the same
without the variable passes.  So the gate refused every `-a` commit
in the tree, for a reason that says nothing about the tree — the case
the test's own docstring names: *a hook that fails for the wrong
reason also refuses*.

**And the reproduction wrote into the tree.**  Pointing
`GIT_INDEX_FILE` at the real index made the scratch test's `git add
a.txt` stage `a.txt` *here*; it was found in `git status` before a
commit took it.  A leak reproduced against the real thing is the leak.

**Resolved the same day:** the test's scratch git runs with every
`GIT_*` variable taken out of its environment.

gate: `test_precommit.py::test_the_hook_refuses_a_commit_when_a_gate_says_no`,
run with `GIT_INDEX_FILE` pointing at this repository's index — red
before the repair, green after.
