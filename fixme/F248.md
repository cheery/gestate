# F248. **[bug]** moving a document's row by retract and assert drops the prose above it — a file's header goes with its first record

**2026-10-03**, found in `git status` after Henri's two minutes with
`examples/gui/drag.ges`: `drag.dots` came back as three bare lines, its
three-line header gone.  The reader attaches the prose above a record to
that record (`records`' `above`), and the file's opening comment is
above the first one; `place`'s `put` is `retracting` then `asserting`,
so dragging dot `a` retracted its line *with* the header and asserted a
new line with none.

    git show 5aec526:examples/gui/drag.dots | head -4     # the header
    # drag dot a anywhere and let go; the file then starts at `dot  name`

The tests did not see it because their document has no comments
(`test_reactors.py`'s `DOTS`).

**Not fixed.**  Two ways out, neither taken today: `retracted` keeps the
removed record's `above` for the record asserted in the same step, or a
move of a non-key field goes through `documents.moved` — which today
retunes only key fields, and only on `.notes` record words
(`notes.retune`).  The note hand's `MoveTo` does not have this defect:
it rewrites the line in place.
