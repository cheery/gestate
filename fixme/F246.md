# F246. **[bug]** `!` over three or more signals refuses a lifted function that runs a comprehension over a set

**2026-10-03**, found desugaring the drag slice's root
(`card:gui-is-difficult.md` §"Built — a drag, as a reactor with a
stored mode"): `!view m0 m1 m2 dots`, where `view` reads a dot's `x`
through a lens whose `get` is a comprehension over the document's set,
did not compile.  Two signals compile; three refuse.

    python - <<'P'
    import sys; sys.path.insert(0, ".")
    from gestate.gui import Substrate
    base = """
    h : Chan Event
    h = chan
    a : Sig Int
    a = scanE (n e => n + 1) 0 (wait h)
    d : Chan (Set Int)
    d = chan
    ds : Sig (Set Int)
    ds = {} ::: mkSig (wait d)
    cnt : Set Int -> Int
    cnt s = length (elems (for (x in s) {x}))
    two : Int -> Set Int -> Sub
    two x s = Rect 10 10 (RGB x (cnt s) 0)
    three : Int -> Int -> Set Int -> Sub
    three x y s = Rect 10 10 (RGB x (cnt s) y)
    substrate : Sig Sub
    """
    Substrate(base + "substrate = !two a ds")        # compiles
    Substrate(base + "substrate = !three a a ds")    # refused:
    # '_m204#lift2' is a monotone variable and cannot be used in the
    # argument of an ordinary (`->`) function ...
    P

*Suspected:* the three-or-more path pairs the signals with `Both`
(`desugar.py`, the left fold of `zipSig`s) and unpacks them through a
lambda whose binder the checker reads as monotone; the two-signal path
does not pair.  Not chased.

**Worked around, not fixed:** `reactors._root` gathers the modes into
one tuple signal first, so every `!` it writes takes two signals; the
control `doc/trial/reactors/drag-today.ges` does the same by hand.
