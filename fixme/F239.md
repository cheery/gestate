# F239. **[bug]** the formatter wraps a tuple pattern at the head of a cons pattern in brackets, and again on every pass

Found 2026-09-16 by `test/fmt/test_roundtrip.py` on `gestate/rules.ges`:

    lookupCons name table = case table of
        Nil -> Nothing
        (n, cons) :: rest -> case n == name of

is formatted as `[(n, cons) :: rest] -> …`, which parses as a list
pattern — a different program — and the second pass makes it
`[[(n, cons) :: rest]]`.  Neither round trip holds.  The file was
rewritten to match `entry :: rest` and then `(n, cons)` on its own,
which formats stably; the formatter is what is wrong, and the pattern
is a legitimate one.

gate: none yet — the two round-trip tests will hold it once it is
fixed, if a source file in the tree carries the pattern; none does now.
