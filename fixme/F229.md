# F229. **[resolved]** a gesture could write a value the document's own rules refuse into a clean `.notes` file, and say it had succeeded

Found 2026-09-13 while taking refusals as constraints
(`card:gui-is-difficult.md` §"LPS, read").  Every gesture's write goes
through `Session._write_included`, which called `notes.canonical`, and
`canonical` hands a text the parser refuses back unchanged — on purpose,
so that a gesture still lands on a file with a mistake elsewhere in it.
The side of that nobody wrote down: a gesture that *introduced* the
mistake was written too.

**Witnessed on `arc.notes`**, with the new check taken out again:
`transpose __nb_pitch_0__ - <tick> 80 128` answered
*"transpose: arc.notes — key 80 → 128 on line 95"* and wrote `key 128`,
outside `note`'s declared `key (Range 0 127)` — the parser refuses that
line when it is typed.  `transpose` carried no bound of its own.  `bars`
did carry one, a hand-written *"a section does not shrink past its
notes"*, which is the only reason a shrink over a full bar was refused.

So `card:relational-model.md` scar 5 — *the second writer skips the
constraints* — was half paid: every write did end in the parser, and the
parser's refusal was then ignored.

**Resolved the same day.**  `_write_included` parses the result first
and refuses the gesture in the parser's words when the file was accepted
before it; a file already refused still takes a gesture, as `canonical`
meant.  `bars`' copy of the rule is gone.  The selection a gesture
stages with `_follow` becomes pending only when the write lands, so a
refused gesture leaves no selection waiting for a rebuild that will not
come.

gate: `test_drawnscores.py::test_a_gesture_that_would_put_a_mistake_into_a_clean_file_writes_nothing`
and `test_drawnscores.py::test_a_section_does_not_shrink_past_its_notes_and_grows_freely`
— both red with the check made a no-op, green with it.
