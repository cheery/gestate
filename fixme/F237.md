# F237. **[bug]** `audioperform <piece> --peak` and `--oracle` refuse a scored piece with an unresolved name at a "prelude line", where `-o --seconds N` renders it

Found 2026-09-16 while counting zero changes for `card:types-in-the-host.md`.

    python -m gestate.audioperform examples/audio/moods.ges --peak --seconds 1
    gestate: UnresolvedName: Unknown global '|*' (not defined as a supercombinator or class method)
    while checking `phraseOf` (at prelude line 2968:18)

    python -m gestate.audioperform examples/audio/arpeggiator.ges --oracle --peak
    gestate: UnresolvedName: Unknown global 'below' (not defined as a supercombinator or class method)
    while checking `anyOf` (at prelude line 2939:18)

`phraseOf` and `anyOf` are the pieces' own definitions, and `|*` and
`below` are `music.ges`'.  The same two pieces render through `-o
out.wav --seconds 1` — *score (dynamic): performed across `bass`,
`lead`, 1.0s* — so the piece is fine and the door is not.
`audioperform.main` sends `--golden`, `--peak` and `--oracle` to
`_oracle_main`, and *suspected*: that path compiles through the synth
library without the music stack in front, so a scored piece's own
lines are checked as if they were prelude and fail on the first music
operator.

Two things wrong, either of which is enough: a scored piece cannot be
peaked or rendered through the oracle, and the refusal names a
*prelude line* for a line the author wrote in the piece.  A door that
cannot take a kind of file should say which door can — the memory
`doc/memory/gestate-verify-workflow.md` already says `-o` is the one for
scored synths, and the program does not.
