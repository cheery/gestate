# F206. **[bug]** the score box reads a note-file note as a bare key: velocity 64 and no manner, whatever the line says

Measured 2026-09-06, `examples/audio/arcnotes.ges` and `arc.notes` opened
alone alike: the compiled roll of `A.melody` reports every event with
velocity `64` and manner `0`.  Line 11 of `arc.notes` says `manner accent`,
its generated line reads `'(fromNote 68 5 2)`, and the leaf's own atoms
say `2` — the picture never drew the accent's mark over that note, and
never has.  `audio.ges` says what the answers should be: `Notable Tone`'s
`noteVel` is `floor (loudness lv * 127.0)` — 111 for `ff`, 95 for `f` — and
`manner` is the third field.

    python3 -c "from pathlib import Path; from gestate import notes; from gestate.scorebox import build_rolls, asks
    src, o = notes.expanded(Path('examples/audio/arcnotes.ges').read_text(), Path('examples/audio'))
    r = build_rolls(src, asks(src)[:1], 44100, 0)[0]; print(sorted({e[4] for e in r.events}), sorted({e[5] for e in r.events}))"
    [64] [0]

So the payload the box reads is not the `Tone` that `fromNote` builds.
`64` and `Plain` are what `instance Notable Int` answers for a bare note,
which points at the box's generated reader (`__nb_read__`) or the
unassigned twin resolving `fromNote` against the wrong instance — the same
shape as F136, a constrained call dispatching to the wrong instance
silently.  **Suspected, not confirmed**; the number is the fact.

Found holding `card:notes-editor.md`'s data road to the compiled one:
the two agreed on every onset, offset, leaf and key and disagreed on
every velocity and manner, and the file settled which was right.  The
data road says what the file says; the compiled road still draws a
`.ges`-written `'(Tone …)` correctly (`test_annotations.py`).

gate: `test_drawnscores.py::test_the_data_road_says_what_the_file_says_about_loudness_and_manner`
holds the data road; nothing yet holds the compiled road on this, and the
repair owes a test that a `.notes` accent draws its dot through it.
