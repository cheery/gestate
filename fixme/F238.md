# F238. **[resolved]** the reflector's two refusals name no line — a type with a variable, a monotone arrow — because its first caller, the zero rule, holds a type and no span

Filed 2026-09-16 with the reflector itself (`stage.reflect`,
`card:types-in-the-host.md`).  The two complaints are the author's — a
polymorphic definition whose type was asked for as a value, a `~>`
where `Type` can only say `->` — and each should land under the
definition's signature.  `changes.zero` is handed a `types.Type` off an
annotated node and nothing that says whose; the place is on the
supercombinator the transform is walking, which the transform knows
and does not pass down.  Carry the name through and the two refusals
place themselves.  Until then they are `unplaced`, and this is the
number that owes it.

## Resolved — 2026-09-16

The transform enters each supercombinator knowing its name and its
signature, and the signature carries the span the parser gave it; so
`SeminaiveCtx` now carries a `place` — `` in `f` (at 12:0)``, 0-based in
the assembled text like every compiler complaint, for
`audiospans.in_source` to move back into the author's file — set as the
transform enters a definition and kept through `bind` and `enter_box`.
Every zero change asked for inside carries it: a `for`'s element, a
dead branch, and a dummy's fields, which add the constructor's name.
`Changes.zero` hands it to the rule and the rule to `stage.reflect`,
whose two refusals interpolate it, which is the ledger's own convention
for a placed complaint.

gate: `test/test_changes.py::test_the_transform_hands_each_definition_s_place_to_the_zero_rule`
— the transform's places captured on a small program, every one
naming a definition and the one ask placed at `main`'s line; and
`test_a_type_with_a_variable_is_refused_and_an_untyped_node_is_unit`,
whose refusal now reads the definition and its line.
